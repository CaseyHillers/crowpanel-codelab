Optional appendix · outside the two-hour course

Back up and restore ESP32 flash

Keep a complete flash snapshot before switching projects. For everyday editing, also download your Python sources: a binary backup is not a folder you can browse in Windows Explorer.

Optional advanced workflow. No commands run from this page. Reading flash interrupts the running application and can reset the board; restoring replaces its stored contents. Do this only when you are ready and authorized.

Before you start

  1. Use an approved installation of esptool 5.x. See Espressif's installation guide. This tool is not needed for the normal browser workshop.
  2. Stop the running project and disconnect the workshop browser's serial connection. Close other serial tools.
  3. Find the board's current port in Windows Device Manager. COM7 below is an example; substitute your actual port. Use a reliable USB data cable and steady power.
  4. Open PowerShell in a private backup folder. Choose a new descriptive filename for each backup so you do not overwrite an earlier snapshot.

1. Back up the whole flash

esptool --port COM7 --baud 460800 read-flash 0 ALL esp32s3-backup_stock_timer_goog_arm_qcom.bin

0 starts at the beginning; ALL detects the flash size. Wait for successful completion. Save the detected chip/flash size and file size alongside a description of the project and board revision.

Record a checksum to detect later file damage:

Get-FileHash .\esp32s3-backup_stock_timer_goog_arm_qcom.bin -Algorithm SHA256

Store the binary and checksum securely. A full image includes firmware and stored project files/data, potentially passwords. It excludes unsaved RAM/editor changes and eFuses. A completed read alone does not demonstrate that a restore will boot.

2. Restore that snapshot later

This overwrites the board's current flash contents, including startup code and incident history. Back up the current state to a different filename first. Use the original board and its matching image; do not assume an image is portable between board revisions.

Check the saved checksum, close serial connections, then deliberately run:

esptool --port COM7 --baud 460800 write-flash 0 esp32s3-backup_stock_timer_goog_arm_qcom.bin

The filename must match your actual backup. If you named it esp32s3-backup.bin, use that name instead. Do not add an erase command or force/protection-bypass flags.

Wait for writing and verification to finish successfully. Reconnect power only after completion, reconnect the browser, and check the physical display and controls. The restored startup program may run and access Wi-Fi immediately.

If something fails

Check the port, cable and serial ownership. For transfer errors, retry with --baud 115200. Stop on secure-boot, encryption or compatibility errors and consult your administrator and the official esptool command reference; protected devices need a device-specific recovery plan.
