macOS Find the port · enable the WCH extension if needed

Open Terminal. Compare the ports with the board unplugged, then plugged in:

ls /dev/cu.*

Look for a new /dev/cu.usbserial-… or /dev/cu.wchusbserial… port. Bluetooth and debug-console ports aren’t the board.

No new port? Open System Information → USB. Our workshop board appears as USB Serial, vendor 0x1A86, product 0x7522. If it isn’t listed, try another data cable or USB port first.

  1. Download the official WCH macOS driver. Confirm its current release supports your macOS version and USB product ID.
  2. Follow the installer. If prompted, copy the app to Applications, open it, then select Install.
  3. Open System Settings → General → Login Items & Extensions → Driver Extensions ⓘ (called Drivers on some versions). Enable CH34xVCPDriver (WCH), approve prompts, and restart if requested.
  4. Unplug and reconnect the board. Run ls /dev/cu.* again.
Installed, but still no port?

The driver may be waiting for approval. Check:

systemextensionsctl list

For cn.wch.CH34xVCPDriver, [activated waiting for user] means approval is pending; [activated enabled] means the extension is enabled. Then verify the serial port separately.

If macOS asks to allow the USB accessory, approve it if your organization permits. If extension approval is managed or blocked, contact IT; don’t weaken security settings.

Windows Find the COM port in Device Manager
  1. Open Device Manager → Ports (COM & LPT). Reconnect the board and look for a new USB serial entry, such as COM5.
  2. If no port appears, inspect Other devices and USB entries. Open the device’s Properties → Details → Hardware Ids. Our workshop interface is USB\VID_1A86&PID_7522.
  3. Try Update driver → Search automatically for drivers. If no matching driver is found, use a signed driver from WCH whose supported hardware IDs include your device; follow the full guide below. Don’t select a driver just because its name looks similar.
  4. Reconnect and confirm a new COM port appears without a warning icon. Select that port in the workshop’s chooser.

No USB entry at all? Try another data cable and USB port. Admin approval or an organization-approved driver package may be needed. Don’t disable driver-signature enforcement.

WCH official Windows CH340/CH341 driver · Confirm its hardware-ID support before installing.

Linux Check USB detection, the serial node, and permissions

In a terminal, compare USB devices before and after reconnecting:

lsusb

Our workshop interface reports 1a86:7522. Check for a new serial node:

ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null

Linux’s upstream ch341 driver includes 1a86:7522; expect a node such as /dev/ttyUSB0 when it binds. Your distribution’s kernel and configuration still matter. If USB appears but no serial node does, use your distribution’s supported driver/kernel path; don’t build or install a vendor module preemptively.

Port exists but access is denied? Inspect its owner/group and your groups, replacing the example node with yours:

ls -l /dev/ttyUSB0
id -nG

Your distribution may use dialout or uucp. Ask your administrator to grant the appropriate serial access; sign out and back in if group membership changes. Don’t use chmod 666 or run the browser as root.

Use a desktop Chrome/Edge build with Web Serial support. Browser sandbox/package permissions can also block serial access; follow your distribution’s supported setup rather than disabling its sandbox.
